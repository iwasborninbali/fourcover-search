# fourcover-search

An open-source pipeline, with no Magma dependency, for finding rational points of large height on elliptic curves over Q. It
goes through four-covers: PARI 2-descent, then C. D. Long's relative four-descent, then reduction, then an Elkies-type
lattice search on the intersection of two quadrics in P³.

With it we found generators for two curves that were open in the S6 Mordell data of Best and Matschke
([ec-data-S6 issue #3](https://github.com/elliptic-curve-data/ec-data-S6/issues/3)):

| curve | conductor | ĥ(generator) (PARI normalization) | search bound H on the four-cover | status |
|---|---|---|---|---|
| y² = x³ + 730033053750 | 389577988800 | 167.3053526503… | 3·10⁹ | E(Q) = Z·Q, proved |
| y² = x³ + 428843415 | 97394497200 | 217.9557848342… | 2·10¹² | E(Q) = Z·Q, proved |

The 3-isogenous partners, y² = x³ − 27038261250 and y² = x³ − 11578772205, are generated by the images of these points.
The coordinates, the proofs and the scripts that check them are in [`results/`](results/).

## What is in the box

| path | what |
|---|---|
| `src/elkies4q.c` | the search. It traces the real locus of Q2 = Q3 = 0 on S³ and cuts it into segments. Each segment gets an osculating box (tangent, second-difference normal, complement), with the segment length adapted so that the box volume stays about VOL. Geometry and LLL are done in `__float128`, then Fincke–Pohst enumeration, then an exact `__int128` check of every candidate. Cost grows like H^(2/3) segments. |
| `src/elkies4.c` | the first version: double precision, both normals given the same width, cost about H^(4/5). Its H·10⁻¹⁶ safety margin dominates the box once H ≳ 10¹⁰. Use it where `__float128` is unavailable (e.g. Apple arm64). |
| `pipeline/export_world.gp` | PARI `ell2cover`: the 2-covers v² = R(t) of E with exact maps to E, as JSON |
| `pipeline/search4.py` | Sage: Long's relative four-descent above one 2-cover, reduction of each soluble four-cover (LLL against the trace form), the reduced quadrics for the search, and exact verification of found points down to E |
| `pipeline/dense_solve.py` | Sage: exact solution of the rare "dense" slices that the search hands over |
| `pipeline/run_world.sh` | all of the above, end to end, for a ladder of bounds H |
| `tests/` | regression tests (run in CI on every pull request) |
| `bench/` | the benchmark case and reference timings |
| `results/` | the two curves: world files, reduced four-covers, generators, certificates, logs |

**Completeness is not certified.** The searches are designed to find every primitive integer point with |u|₂ ≤ H on the
reduced four-cover. However, real components are found from random seeds, the box widths rest on numerical curvature
estimates, and H is not an enforced cutoff. A null result is evidence, not proof. Every point that is reported has been
checked exactly.

## Quick start

```
tests/run_tests.sh                   # builds src/elkies4q and src/elkies4, runs the regression cases
```

`elkies4q` needs gcc with `__float128` and libquadmath (Linux x86_64). The input is the 20 integer coefficients of Q2 and
Q3: the coefficient of u_i u_j for i ≤ j, Q2 first.

```
src/elkies4q H VOL SEEDS [F0 F1] < cover.coef     # e.g. src/elkies4q 3e9 64 200 < results/k730033053750/cover-c1-156.coef
```

The output has one `POINT u0 u1 u2 u3` line per primitive point found, `DENSE` lines (slices for `dense_solve.py`),
`COMPONENT` lines and a final `DONE` line with counts. With `F0 F1`, only the fraction [F0, F1) of each real component is
searched, so several cores can split one curve.

### A whole curve

Requirements: PARI/GP ≥ 2.15, SageMath, and a checkout of
[long-algorithms/elliptic-descent](https://github.com/long-algorithms/elliptic-descent) (tested at commit `882a0dac`).

```
echo 'A = [0,0,0,0,730033053750]; NAME = "M730033053750";' | cat - pipeline/export_world.gp | gp -q -f > world.json
export SAGE_PYTHON="sage -python" ELLIPTIC_DESCENT_SRC=/path/to/elliptic-descent/src
pipeline/run_world.sh world.json c1 "1e8 1e9 3e9"
```

This prints `FOUND ...` and `POINT_ON_E x y height h` when a point appears. To choose H, a useful rule of thumb on our
reduced four-covers is log max|u| ≈ ĥ/8 + c, with c between −1.3 and +0.6 in the two cases above. ĥ can be predicted from
BSD (`ellbsd`, `ellanalyticrank`).

## Reproduce the two results

```
cd results/k428843415
python3 check_exact.py           # Python stdlib: points on curves, isogeny, torsion, Q not in pE(Q) for p <= 47
python3 height_certificate.py    # Python stdlib: Voutier–Yabuta height bounds in exact rational arithmetic, index <= 7
gp -q -f < certified_rank.gp     # PARI 2.19: rank <= 1 with certified class-group data (bnfcertify = 1)
```

Together these prove E(Q) = Z·Q without Sage. `evidence/` holds the original logs, including Sage/mwrank saturation as an
independent second proof of index 1. Each `generator.json` records how the point was found.

## Benchmarks

See [`bench/README.md`](bench/README.md). On one core of an x86_64 VM:

- **H = 10¹⁰, k = 428843415 four-cover:** `elkies4q` finished the null run in 59 min, against about 8 h for `elkies4`.
- **H = 3·10⁹, k = 730033053750 four-cover:** `elkies4q` re-finds the known point in about 21 min (VOL 64).

We have **not** compared these programs with any other implementation. Measured comparisons with other open-source point
searchers are a welcome contribution.

## Contributing: people and agents welcome

Improvements are welcome: faster or provably complete searches, better reduction, ports (arm64 without `__float128`),
more test cases, new solved curves. See [CONTRIBUTING.md](CONTRIBUTING.md).

The cycle: open a pull request. CI builds the code and runs the regression tests. A maintainer reviews the change and
re-runs the benchmark. If it passes, the change is merged and released as a new version, archived on Zenodo with a DOI.
AI agents are explicitly welcome as contributors. Please say in the pull request that you are one, and who operates you.

## Provenance and credit

The search code, the pipeline and the proofs were written and checked by AI agents (Anthropic Claude; OpenAI Codex
cores for the adversarial audits) under the direction of the author of record, who takes responsibility for the content.
The four-descent is C. D. Long's `elliptic-descent` (MIT), used unmodified. The 2-descent and the certified rank bounds
are PARI/GP. The method follows N. D. Elkies, *Rational points near curves and small nonzero |x³ − y²| via lattice
reduction* (ANTS-IV, 2000). The height bounds are from P. Voutier and M. Yabuta (arXiv:1305.6560). The curves come
from the list of unresolved cases in A. J. Best and B. Matschke's S6 data. We make no claim of a new algorithm.
